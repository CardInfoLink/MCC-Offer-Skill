# 列表结果展示

查询、分页、相似推荐三个场景共用的展示规则（详情由 `detail.md` 自己展示，不依赖本文件）。这不是逐字套用的模板：回复由大模型根据用户问题、接口原始响应、上下文和平台风格生成，措辞、结构、详略可调整，但**不改变接口事实、不编造内容**。

响应怎么判定（退出码、`code`）见 `common.md`；哪些内容不能出现在回复里见 `SKILL.md` 的“用户可见输出”；接口字段见 `api/*.md`。

## 通用规则

- `offerUrl` 只用服务端返回值，不改域名、路径或 query。
- 内部匹配分、`matchScore`、`relevanceScore` 不展示，也不当作优惠力度或评价。
- 日期按服务端返回值展示，不延长有效期，不推荐已过期的 Offer。
- 不复述意图分析和请求参数；这些内容本身是权益适用条件时除外（例如 Offer 只适用于某银行）。
- 用 Markdown 组织回复。

## 响应场景表

`isDefault` 的来源记在会话状态里（查询词 / 标签 / 无主题 / 分页 / 推荐），按下表选话术：

| 响应情形 | 怎么说、怎么展示 |
|---|---|
| 有列表，`isDefault=false` | 按下面的“列表展示” |
| `isDefault=true`，来自**查询词** | 先说“没有找到与「关键词」相关的权益”，再展示这几条参考推荐；建议换个说法，或描述想要的类型 |
| `isDefault=true`，来自**标签** | 先说“没有完全符合您条件的权益，以下是参考推荐”；建议放宽地区、银行或时间条件。所提地区不在 `regions.txt` 时，再加一句“目前可能不支持该地区”（只是提示，不要断言“不支持”“未覆盖”） |
| `isDefault=true`，**无主题**（只有条件，或什么都没说） | 说明“还没确定想找哪类权益，先看看这些参考推荐”；有条件时补一句“告诉我想找的类型或品牌，我再按香港、工行卡帮您筛”（兜底本身不受地区、银行、时间约束，不要说这些推荐在该范围内） |
| `isDefault=true`，来自**分页**（页号越界，或缓存过期后重新匹配没有结果） | 说“没有更多符合条件的权益了”，再展示参考推荐 |
| `isDefault=true`，来自**相似推荐**（基准 Offer 已失效或没有相似项） | 说明找不到相似权益，以下是通用推荐 |
| `offers` 为空 | 明确说没有可展示的权益，建议调整条件；不补造内容 |

`isDefault=true` 时服务端最多随机给 3 条，没有 `queryCacheId`，不分页，不要询问“是否查看更多”。

兜底是随机的，**不受**用户给的地区、银行、时间约束，不要把它们说成符合这些条件。列表里有 Offer 就必须把它们展示出来；只有 `offers` 为空才按上表最后一行说明，**没有列表时不要说“先看看这些推荐”**。

## 回复结构

最终回复是**一条消息**，从上到下最多三块：

1. **一句说明（可选）**：点明沿用的条件，或按上表说明 `isDefault`。没有需要说明的就省略，直接进列表。
2. **Offer 列表**（见“列表展示”）。
3. **一句收尾（可选）**：`hasMore=true` 就问“还要继续查看更多权益吗？”；否则可以提示“想了解哪个，告诉我第几个”。只选其一，只写一句。

不要写：开场复述需求（“我看到您想找……”）、列表后的总结复述（“以上涵盖了……”）、对处理动作的汇报（保存状态、清理文件、“已完成”），也不要把同一段话说两遍。

## 点明生效的条件

多轮对话里有**沿用**上一轮的条件时（银行、地区、时间、主题），回复开头用一句自然语言点明，让用户有机会纠正，例如“仍按香港、工行卡为您查找”。只提沿用的，不提换话题时丢弃的；用户这一句自己说的条件不必复述；不展示 `filters` JSON。

结果落到兜底（`isDefault=true`）且其中有沿用的条件时，再补一句建议放宽，例如“当前限定了香港和工行卡，要不要去掉银行限制再看看？”。

## 列表展示

不展示 `currentPage`、`totalPages`、`queryCacheId`、`hasMore`，不主动说“第几页”“共几页”。每页最多 5 条，不对服务端顺序重新排序。

每项 Offer：

- `merchantName` 非空时标题用 `【商户名称】Offer 标题`；为空时只写 Offer 标题，不补造商户。
- 附一段简短简介：优先把 `description` 压缩整理；`description` 很短就原样使用。不添加接口没有的事实，不臆造“适合人群”“主题分类”或权益条件，也不根据 `intentTags` 反向生成“适合：……”。
- `offerUrl` 用 Markdown 链接，文字用“查看权益”或“参与详情”。平台拦截链接时不要输出 `[blocked]`，改写为“参与链接暂不可用”，保留其他事实信息。

结尾怎么收，见上面的“回复结构”。

```markdown
## 为你推荐

### 【香港山泉度假酒店】香港温泉酒店万事达专享礼遇

- **简介**：使用万事达信用卡预订香港温泉酒店，可享住宿折扣及亲子温泉体验。
- **参与方式**：[查看权益](https://example.com/offer)
```

## 出错时

- 退出码 `13` / `14`，或其他非 `S000000`：说明权益数据服务暂时不可用，保留当前条件，建议稍后重试。
- 查询、推荐、分页不会因参数不规范而报错，**不要提示用户“参数错误”**；这类情况服务端已按 `isDefault=true` 兜底，按上面的场景表说明即可。
