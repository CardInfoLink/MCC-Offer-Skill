# 详情能力

处理“某个 Offer 的详情”。场景路由已由 `SKILL.md` 完成，本能力不做意图解析，也不依赖 `result.md`（详情的展示规则就在本文件）。

## 依赖

进入本能力后，在同一轮里一次性并行读完：`common.md`（脚本调用、响应判定、会话状态、清理）、`references/api-offer-detail.md`（请求与响应字段）、`config/client.conf`（接口地址）。同会话已读过且没变的不用重读。

## 处理流程

1. **确定 `offerId`**：从会话里最近展示的列表按用户的指代解析：“第 N 个”按序号，“星巴克那个”按商户或标题唯一匹配。对应不上或有多个候选时，列出候选标题请用户选一个，不猜。
2. 按 `references/api-offer-detail.md` 用 `GET` 调用，请求 ID 前缀 `detail`。
3. 读取 `RESPONSE_FILE`，按 `common.md` 判定响应后按下表处理。
4. 把当前 `offerId` 和用户追问所需的基本事实存入会话状态。

| 响应 | 做法 |
|---|---|
| `S000000` | 按下面的“详情展示”回复；`offerUrl` 原样提供 |
| `F080104`（不存在、已下线或已过期） | 说明该权益已不可用，建议回到列表重新选择或重新查询；不编造详情 |
| 其他失败（退出码 `13` / `14`，或其他非 `S000000`） | 说明权益数据服务暂时不可用，保留当前条件，建议稍后重试 |

用户接着问“还有类似的吗”：把当前 `offerId` 作为 `baseOfferId`，转 `recommend.md`。

## 详情展示

回复是一条消息，用 Markdown，不改变接口事实、不编造内容。按用户的问题调整顺序（问有效期先写有效期，问适用范围先写银行和地区），不遗漏接口里明确返回的限制条件。

字段：权益类型、适用银行、适用地区、有效期、参与条件、权益简介、关联标签（Offer 自带的标签名属于权益事实，可以展示）、参与链接。

```markdown
## 【香港山泉度假酒店】香港温泉酒店万事达专享礼遇

- **权益类型**：折扣
- **适用银行**：ABC　**适用地区**：香港
- **有效期**：2026-10-01 至 2026-12-31
- **参与条件**：使用指定万事达信用卡支付
- **权益简介**：使用万事达信用卡预订香港温泉酒店，可享住宿折扣及亲子温泉体验。
- **关联标签**：温泉度假、酒店、亲子

[查看权益](https://example.com/offer)
```

- `merchantName` 非空时标题用 `【商户名称】Offer 标题`；为空时只写 Offer 标题，不补造商户。
- 日期按服务端返回值展示，不延长有效期，不推荐已过期的 Offer。
- `offerUrl` 用 Markdown 链接，文字用“查看权益”或“参与详情”。平台拦截链接时不要输出 `[blocked]`，改写为“参与链接暂不可用”，保留其他事实信息。
- 不复述请求参数，不写对处理动作的汇报（保存状态、清理文件、“已完成”）。

## 不允许

- 不重新做意图解析。
- 不自行拼接、改写或替换 `offerUrl`。
- 不展示 `relevanceScore`，也不把它当作用户评价或优惠力度。
